# Amino Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Amino, a workout scheduler whose "mark done" action turns the trained muscles red on a 3D body, fading to grey over 48 hours.

**Architecture:** npm-workspaces monorepo. `packages/shared` owns muscle IDs, the soreness math and zod schemas. `apps/api` is Express with layers routes, controllers, services, repositories (Drizzle on Neon Postgres). `apps/web` is React with feature folders, TanStack Query for server state, and a React Three Fiber scene that only receives a `Record<MuscleId, number>`.

**Tech Stack:** TypeScript (strict, ESM), Node 22+, Express 5, Drizzle ORM and drizzle-kit, `pg`, zod, pino, Vitest, Supertest, React, Vite, Tailwind CSS, Motion (`motion/react`), three, @react-three/fiber, @react-three/drei, TanStack Query, Testing Library. Use the latest stable release of each at install time.

**Spec:** `docs/superpowers/specs/2026-11-04-amino-design.md`

## Global Constraints

- Node `>=22`; every package `"type": "module"`; `strict: true` in `tsconfig.base.json`.
- Workspace names: `@amino/shared`, `@amino/api`, `@amino/web`. `@amino/shared` exports TypeScript source (`exports` points at `src/index.ts`); the API bundles it with tsup.
- All routes live under `/api/v1`. Every failure returns `{ "error": { "code": string, "message": string, "details"?: unknown } }`.
- Every table has a UUID primary key, `created_at`, `updated_at`. Every repository method takes `userId` first.
- `MuscleId` values (kebab-case): `chest`, `upper-back`, `lats`, `traps`, `shoulders`, `biceps`, `triceps`, `forearms`, `abs`, `obliques`, `lower-back`, `glutes`, `quads`, `hamstrings`, `calves`.
- Recovery window `RECOVERY_HOURS = 48`. Role weights: primary `1.0`, secondary `0.5`. Overlap takes the max, capped at 1.
- `GET /workouts` requires `from` and `to` (`YYYY-MM-DD`), `from <= to`, span at most 62 days.
- Monochrome tokens as CSS variables: `--bg #0b0b0b`, `--surface #141414`, `--border #262626`, `--text #ededed`, `--muted #8a8a8a`, `--body-grey #8a8a8a`, `--soreness-red #e5262d`. Red appears nowhere else.
- Secrets: `DATABASE_URL` and `TEST_DATABASE_URL` only in gitignored `apps/api/.env`. `.env.example` holds placeholders. Never write a real connection string into a tracked file, a test, or a log line.
- Integration tests run only against `TEST_DATABASE_URL` (a separate Neon branch) and are skipped with a clear message when it is unset.
- Commit messages carry no co-author or AI attribution line of any kind (user instruction).

## Review Focus

1. Completing an already completed workout again must leave `completed_at` unchanged and return 200 (Task 4).
2. An event exactly 48 hours old, or older, contributes 0 and is excluded by the server query (Tasks 1, 5).
3. A client clock behind the server makes `completedAt` appear in the future; intensity must clamp to at most 1, never exceed it or become NaN (Task 1).
4. A malformed UUID or an unknown or foreign workout id returns a 400 or 404 envelope, never a 500 (Task 4).
5. WebGL unavailable or context lost shows the muscle-bar fallback while the schedule keeps working (Task 9).
